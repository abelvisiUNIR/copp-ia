# ADR-001: Lark + LALR para el parser DSL

> Provenance: `copp-ia@main@6046648`. Fuente: `docs/teleflow-adr.typ:96-109`,
> `TeleFlow-Arquitectura-v1.0.md:832-839`. Implementación: `teleflow/dsl/`.

## Context
El `.tflow` es el corazón del producto. Se necesita un parser legible, performante y
extensible cuya gramática sirva de documentación viva.

## Decision
Usar **Lark con algoritmo LALR** como parser del `.tflow`. La gramática EBNF vive en
`teleflow/dsl/teleflow.lark` y es la **única fuente de verdad del lenguaje**.

## Rationale
Lark ofrece la mejor relación entre legibilidad (EBNF nativo en Python), performance LALR
determinístico en producción y extensibilidad. El Transformer de Lark convierte el parse
tree en dataclasses tipados con código mínimo.

## Consequences
- Cualquier extensión del DSL requiere **modificar `teleflow.lark` primero**; el transformer
  se actualiza para cada nueva regla.
- Los errores de sintaxis incluyen línea/columna.
- Tree-sitter se reserva para el plugin de VS Code (Fase 4).
- (hecho, validación) `teleflow/dsl/transformer.py` concentra 180 de los 236 errores de
  `mypy --strict` — los métodos del Transformer (que reciben trees de Lark) no están tipados.
  Ver [[2026-07-09-validacion-doc-vs-codigo]].

## Alternatives
PLY (lex/yacc, más verboso) · Parsimonious (PEG, backtracking sin límite) · Tree-sitter
(ideal para IDE, difícil en runtime Python) · parser combinador manual (frágil).
